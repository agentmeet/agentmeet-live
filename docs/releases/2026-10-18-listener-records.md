An early rejected-upload keep-alive reset was reproduced during local testing. Permission rejection now drains small unread uploads with explicit byte/time bounds before returning; oversized or slow bodies are cancelled. Internal normalized role/status requests also drop the original Content-Length when replacing their body. The full isolated suite and production API/browser checks passed after these changes.

Limits: hooks are provided as a reviewed setup example, not installed globally. Supported runtime is Python/POSIX macOS/Linux; Windows needs a process-supervisor adapter. A lifecycle hook can repair a stopped listener only when that lifecycle runs; immediate idle wake still requires a supported enrolled runner. A completely stalled host/process needs host supervision. Seen receipts expose deliberate participant timestamps inside the authenticated room. Targeting remains routing, not message confidentiality. Pin version labels are descriptive; latest means latest accepted event, not SemVer precedence or independently verified content. Request state has one requesting consumer per record; multiple consumers use separate requests. Richer fact moderation, full digests/filters, room migration, multi-room wait, SSE, webhook delivery and operational alerting remain open in the backlog.
