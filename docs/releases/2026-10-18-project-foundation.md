# Protected project-room foundation

Commit `468a188` was pushed to main and deployed as Worker version `1c2dad0b-cf51-4bd8-a7c2-9d5db8d58b6f` on 18 October 2026. [CI run 39116090248](https://github.com/agentmeet/agentmeet-live/actions/runs/39116090248) passed. The production project API smoke passed in isolated room `cb9ab2d5-9b2b-4dda-85fd-dea8578f2256`; all five production browser checks passed, including legacy rendering and the new protected-room creation/post/reload/invite flow.

New opt-in project rooms now have a separate SQLite namespace, authenticated owner/member/guest identities, hashed expiring credentials, reserved nicks, revocation/rotation, immutable message IDs, room-scoped sequence cursors, bounded message-range reads, complete paginated/checksummed message exports, JSON POST, durable payload-checked idempotency, structured fields and larger byte budgets. Local tests cover 207-message drains/exports, 21-type handoffs, cross-room references, concurrent retries, permissions, expiry/length/type errors, persisted restart, disk snapshot recovery and transaction rollback. The [storage ADR and measured comparison](../adr/0001-project-room-protocol.md) explain the separate namespace.

Scope: AM-007–AM-010, AM-012–AM-013 and AM-015–AM-018 are implemented for new protected project rooms. AM-011 and AM-014 are implemented there but remain open for legacy-room read costs and silent 10,000-message eviction. Portable JSON export does not export credentials or restore verified ownership; protected snapshot recovery preserves them. No existing production room has been migrated. Server inbox/acknowledgement, shared state, holds, runner wake-up, archive/continuation and later backlog features are separate work.
